# 长截图方案与调研

2026-10-07。目标：保留 Simple 的原生白色工具条、绿色完成状态和六种标注，仅增加一个长截图入口。

## 源码与社区

当前 Simple 没有滚动实现；原版 v4.3.0 有 ScrollCaptureController（786 行）、ScrollFrameAnalyzer（152 行）以及独立 HUD 和预览。沿用 GPL-3.0 的像素分析代码，重新实现小型手动滚动流程，不恢复原版自动滚动、速度配置及复杂编辑器。

- 上游源码：https://github.com/sw33tLie/macshot/tree/v4.3.0/macshot/Capture
- ScrollSnap：https://github.com/Brkgng/ScrollSnap ，选区捕获并排除应用界面。
- Lenscap：https://github.com/rutmehta/Lenscap ，重叠匹配，帧数/像素高度限额。
- Reddit 作者演示：https://www.reddit.com/r/opensource/comments/1kua8bz/ ，自然滚动后保存；社区体验反馈不能证明所有应用兼容。
- Reddit 反馈：https://www.reddit.com/r/macapps/comments/1kr5md8/ ，存在页面拼接问题反馈，因此必须验收重复内容及复杂页面。
- 已搜索 X 的 macshot/ScrollSnap/scrolling screenshot；没有找到可核实的相关原帖，不把搜索缺口当作结论。

## 实现约定

1. 框选后点“长截图”；尚未开始标注时可用，避免丢弃标注。
2. 退出冻结画布，恢复原应用焦点。手动向下滚动，选区保持不变；不模拟滚轮，不需要辅助功能权限。
3. 浮动条仅显示状态、取消、完成；macOS 14/15 用 ScreenCaptureKit 排除自身；macOS 26 使用选区截图接口，工具条和绿色边框完全置于选区外，避免旧的枚举接口返回空屏幕列表。全屏选区需要缩小，为控制条留出约 60 点空间。
4. 连续采集选区，每帧确认足够的重叠和唯一匹配后追加新内容，无需等待两帧静止。静止不追加；向上滚动或匹配失败不改变已接受帧。
5. 有界内存：最多 20,000 像素高度和 40,000,000 像素面积。达到上限提示结束，不截断后静默继续。
6. 完成时等待最后一帧，打开可滚动长图，底部沿用现有工具栏。原像素输出，不拉伸。
7. macOS 14+ 使用 ScreenCaptureKit 排除自身；旧系统显示明确提示，普通截图继续可用。

## 验收

单元测试覆盖精确拼接、重复帧、向上滚动、无重叠、重复图案、尺寸变化、固定页头/页脚和限额。新增 UI 测试检查入口、禁用状态和长图输出。完成本地测试、通用构建及安装；实机网页/聊天、多屏、输入法与实际粘贴分别报告，不能用合成图片测试冒充实机验收。

## 捕获失败复查（2026-10-07）

用户实测报告“捕获失败”，发生在拼接之前。原实现仅有单一捕获接口，且 macOS 26 回调丢弃系统错误。普通截图与上游滚动截图均有 WindowServer 捕获路径，而 Simple 长截图缺失兼容路径。现补上有屏幕录制授权时的兼容捕获，并排除浮动条与边框；一旦切换，整个会话沿用同一接口。失败保留系统错误域和错误码。完成时只提交一次最后稳定帧，避免结果被第二次重复提交覆盖。浮动条取消阴影，避免阴影进入选区。

本次不因捕获失败改写重叠算法。文字加留白的新增回归测试在原算法上已通过；先前纹理窗口成功只能证明受控场景，不能证明用户真实页面成功。

## 连续滚动稳定性方案（2026-10-07）

问题：旧流程在每帧捕获和分析后再等待 220 ms，且只处理连续两帧静止的画面，持续滚动可能丢掉中间重叠。

- 优先用原生 SCStream 连续采集选区，第一帧准备完成后再开始滚动（15 fps、无音频、无光标、排除自身），只接收完整帧；无需新增权限。
- 采集与拼接分开；待处理缓存最多 8 帧，满时保留早期衔接帧并更新最新待处理帧，限制内存。
- 每帧直接验证唯一垂直重叠，不再要求连续静止；匹配失败不推进基准帧。
- 连续采集启动失败、流中断或 500 ms 没有完整帧，退回已验证的兼容截图路径，轮询间隔 60 ms。
- 完成时短暂等待连续采集的最后一帧，停止采集并处理缓存，再提交最后视口。连续模式从头到尾使用连续帧，兼容模式使用单张截图，避免混用不同的输出管线；取消后忽略晚到帧和结果。
- 保留现有工具条、原像素、长度限制和手动滚动；不添加自动滚动和复杂设置。

参考 Snapzy 的连续帧、受限缓存和串行拼接结构：https://github.com/duongductrong/Snapzy/blob/master/docs/SCROLLING_CAPTURE.md 。本次独立实现精简流程；不复制其复杂 HUD、自动滚动、预览栏或全量子系统。

验收：持续移动而无静止帧、处理落后缓存、无重叠后回退恢复、连续窗口滚动、兼容路径连续滚动；真实动态网页、用户触控板和多屏另行确认。

文字回归测试复现了旧稀疏网格受大面积留白干扰的问题。匹配改为采样内容边缘（最多 1600 点），仍要求足够重叠及唯一匹配，不放宽重复内容拒绝规则。

## 减少未找到重叠（2026-10-07）

用户实际体验中提示过于频繁。本次复现了两个可确定原因：1 像素滚动不在原搜索范围内；局部像素变化使整体误差超限。分别补充回归测试，修改前均失败。

- 位移搜索从 1 像素开始，适应慢速滚动和惯性收尾。
- 重叠评分仅剔除误差最大的 10% 采样点，容忍少量局部变化；仍保留足够重叠、最小样本数和竞争位移唯一性要求，重复图案/无重叠继续拒绝。
- 单帧未匹配显示中性等待状态；连续 0.8 秒未恢复才提示回退。恢复追加或回到已接受帧时清除过期的未匹配状态。结束时未匹配的最后帧仍明确标记部分结果。

40 项 Release 测试和双架构构建通过；不把测试通过当作用户实际应用中的失败频率已量化降低。
